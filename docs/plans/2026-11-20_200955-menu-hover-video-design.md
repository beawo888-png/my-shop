# 왕징 전체메뉴 이미지 호버 영상 기획안

**확정일:** 2026-11-20  
**상태:** 사용자 기획 승인 완료, 구현 전  
**대상:** 왕징양다리양꼬치 홈페이지 `/menu`

## 1. 목표

전체메뉴의 대표 메뉴 사진 위에 PC 마우스를 올리면 같은 자리에서 음식 영상이 재생되고, 휴대폰에서는 사진을 한 번 누르면 같은 자리에서 영상이 재생되도록 한다. 메뉴명·설명·가격과 현재 메뉴 분류 구조는 그대로 유지한다.

## 2. 확인한 현재 상태

- 전체메뉴는 5개 분류, 44개 메뉴로 구성되어 있다.
- 메뉴 카드는 `components/menu/full-menu-card.tsx`, 이미지는 `components/menu/full-menu-image.tsx`, 목록 상태는 `components/menu/menu-explorer.tsx`가 담당한다.
- 메뉴 원본은 `data/menu.csv`이며 `scripts/build-menu.mjs`가 `lib/menu-content.ts`를 생성한다.
- 홈페이지 대표영상 4개가 `public/videos/signature/signature-01.mp4`부터 `signature-04.mp4`까지 존재한다.
- 4개 영상 총 용량은 13,914,106바이트(13.27MiB)다. 따라서 메뉴 페이지 진입 시 전부 다운로드하면 안 된다.
- 현재 메뉴 카드는 클릭·호버 영상 기능이 없다.
- 현재 작업 트리에는 사용자의 기존 미완료 변경이 있으므로 구현 시 해당 변경을 보존하고 이 기능 관련 파일만 건드린다.

## 3. 참고 사이트와 적용 방향

`https://nothingbetter.co.kr/`를 현재 원본으로 확인했다. 해당 사이트는 상품 카드 클릭 시 상세페이지로 이동하는 흐름이 주이고, 별도의 유튜브 영상 영역도 사용한다.

왕징 홈페이지에는 이를 그대로 복제하지 않는다. 사용자가 확정한 방향대로 외부 페이지 이동이나 큰 팝업 없이, 메뉴 사진 영역 자체가 영상으로 전환되는 더 단순한 방식으로 구현한다.

## 4. 확정된 사용자 경험

### PC

1. 영상이 연결된 메뉴 사진에 `영상 보기 ▶` 표시를 작게 노출한다.
2. 마우스가 사진 영역에 들어오면 해당 사진 자리에서 영상이 무음으로 자동 재생된다.
3. 마우스가 사진 영역을 벗어나면 영상을 정지하고 처음으로 되감은 뒤 사진으로 즉시 복귀한다.
4. 한 번에 하나의 메뉴 영상만 재생한다. 다른 영상 카드에 마우스를 올리면 기존 영상은 종료한다.

### 휴대폰·터치 기기

1. 영상이 연결된 메뉴 사진을 한 번 누르면 같은 자리에서 무음 영상이 재생된다.
2. 같은 사진을 다시 누르면 영상이 정지·초기화되고 사진으로 복귀한다.
3. 다른 영상 메뉴를 누르면 기존 영상은 종료하고 새 영상만 재생한다.

### 소리

- 최초 재생은 항상 무음으로 시작한다.
- 재생 중에만 작은 `소리 켜기/끄기` 버튼을 제공한다.
- 사용자가 소리를 켜기 전에는 갑자기 소리가 나지 않는다.

### 영상이 없는 메뉴

- 나머지 메뉴 카드는 현재 사진 카드 그대로 유지한다.
- 영상 표시, 빈 버튼, 비활성 안내를 노출하지 않는다.

## 5. 첫 적용 범위

- 현재 홈페이지 대표영상 4개를 재사용한다.
- 실제 영상 내용과 일치하는 대표 메뉴 4개에 우선 연결한다.
- 영상 내용과 메뉴를 임의로 추측해 연결하지 않는다. 구현 시작 시 4개 영상을 로컬 미리보기로 확인하고 메뉴 대응표를 확정한다.
- 향후 `data/menu.csv`에 영상 파일명만 추가하면 최대 6개 이상으로 확장할 수 있게 한다.
- 특정 영상이 어떤 메뉴인지 확실하지 않으면 잘못 연결하지 않고 해당 행을 비워 사진으로 유지한다.

## 6. 콘텐츠 관리 방식

`data/menu.csv`에 선택 컬럼 `videoFile`을 추가한다.

- 값이 비어 있음: 사진만 표시
- 값이 있음: `/videos/signature/<videoFile>`을 메뉴 영상으로 사용
- 예시 값: `signature-01.mp4`

`scripts/build-menu.mjs`는 이 열을 읽어 `FullMenuItem.videoSrc?`를 생성한다. 사용자는 이후 WPS에서 영상 파일명만 바꿀 수 있다. 생성 파일인 `lib/menu-content.ts`를 직접 수정하지 않는다.

## 7. 화면 구성

### 정적 상태

- 현재 4:3 메뉴 이미지 비율을 유지한다.
- 영상 메뉴만 이미지 오른쪽 아래에 작은 반투명 `영상 보기 ▶` 배지를 표시한다.
- 기존 메뉴명·설명·가격 높이와 카드 정렬은 바꾸지 않는다.

### 재생 상태

- 영상은 사진과 같은 4:3 영역을 채운다.
- 음식이 과도하게 잘리지 않도록 기본 `object-fit: cover`를 사용하되, 실제 4개 영상을 확인해 필요한 경우 개별 위치만 조정한다.
- 재생 시작 시 짧은 페이드 전환을 사용한다.
- 재생 중 `재생 중`, `소리 켜기/끄기` 조작을 식별할 수 있게 한다.

### Pencil 우선

코드 구현 전에 기존 `초안` 파일에 다음 두 상태를 추가하고 확인한다.

- PC 메뉴 카드: 사진 기본 상태 / 마우스 호버 영상 상태
- 모바일 메뉴 카드: 사진 기본 상태 / 한 번 누른 영상 상태

기존 Pencil 파일을 교체하거나 이름을 바꾸지 않는다.

## 8. 성능 설계

- 메뉴 페이지를 열 때 4개 영상 전체 13.27MiB를 내려받지 않는다.
- 영상 요소는 필요한 카드에만 만들되 `preload="none"`을 기본으로 한다.
- 첫 호버·탭 때만 영상 URL을 활성화하고 재생을 시작한다.
- 한 번 불러온 영상은 같은 페이지 안에서 재사용해 두 번째 재생을 빠르게 한다.
- `playsInline`, `muted`를 사용해 모바일 전체화면 강제 전환과 자동재생 차단을 피한다.
- 영상 로딩 중에는 원래 사진을 유지하고 작은 로딩 표시만 겹친다.

## 9. 접근성·오류 처리

- 영상 사진 영역은 키보드로 접근 가능한 버튼 역할을 갖는다.
- Enter 또는 Space로 재생·정지를 전환한다.
- `aria-label`은 예: `생양꼬치 조리 영상 재생`처럼 메뉴명을 포함한다.
- `prefers-reduced-motion` 사용자는 호버만으로 자동재생하지 않고 명시적인 재생 조작을 해야 한다.
- 영상 로딩 또는 재생 실패 시 오류 문구로 카드를 덮지 않고 원래 사진으로 복귀한다.
- 소리 버튼과 카드 재생 버튼의 클릭이 충돌하지 않게 이벤트 범위를 분리한다.
- 카테고리 변경으로 카드가 사라지면 재생 중 영상을 즉시 정지한다.

## 10. 구성 요소 경계

- `MenuExplorer`: 현재 재생 중인 메뉴 식별자를 하나만 관리한다.
- `FullMenuCard`: 메뉴 데이터와 활성 여부를 받아 카드 본문 및 영상 지원 여부를 구성한다.
- 새 `MenuCardMedia` 클라이언트 구성 요소: 사진, 영상, 호버·탭·키보드 조작, 로딩·오류·음소거 상태만 담당한다.
- `FullMenuImage`: 기존 사진 fallback 역할을 유지한다.

이렇게 분리하면 영상 동작을 다른 메뉴 데이터와 섞지 않고 독립적으로 시험할 수 있다.

## 12. 구현 순서

1. 기존 4개 영상을 로컬에서 확인하고 실제 음식과 일치하는 메뉴 대응표를 확정한다.
2. `초안`에 PC 호버와 모바일 탭 상태를 추가해 화면 기준을 고정한다.
3. CSV 생성기 시험을 먼저 추가한다. `videoFile`이 비어 있거나 채워진 경우를 모두 검증한다.
4. `data/menu.csv`와 `scripts/build-menu.mjs`에 선택 영상 열을 추가한다.
5. 생성기를 실행해 `lib/menu-content.ts`에 선택적 `videoSrc`가 생성되는지 검증한다.
6. 메뉴 미디어 상호작용 시험을 먼저 추가한다.
7. `MenuCardMedia`와 단일 활성 영상 상태를 구현한다.
8. PC·모바일·키보드·모션 줄이기·로딩 실패 상태의 스타일을 추가한다.
9. 실제 데스크톱과 390px 모바일 화면에서 동작과 레이아웃을 확인한다.
10. 전체 테스트·린트·정적 빌드를 통과시킨다.

## 13. 검증 기준

기능 완료라고 판단하려면 모두 충족해야 한다.

- PC에서 영상 메뉴에 마우스를 올리면 사진 자리에서 무음 영상이 재생된다.
- 마우스를 빼면 사진으로 돌아오고 영상 시간이 초기화된다.
- 모바일에서 한 번 누르면 재생, 다시 누르면 사진 복귀가 된다.
- 한 번에 영상 하나만 재생된다.
- 영상 없는 메뉴는 현재와 동일하다.
- 영상 요청은 첫 상호작용 전에는 발생하지 않는다.
- 영상 오류 시 사진이 유지된다.
- 키보드로 재생·정지 및 소리 조작이 가능하다.
- 390px, 768px, 1440px에서 카드 비율과 문구 정렬이 깨지지 않는다.
- `npm test`, `npm run lint`, `npm run build`가 통과한다.
- 사용자 기존 작업 파일을 덮어쓰거나 되돌리지 않는다.

## 14. 위험과 대응

- **영상과 메뉴 불일치:** 실제 장면 확인 전 연결 금지.
- **초기 로딩 증가:** `preload="none"`과 상호작용 시점 로딩 적용.
- **모바일 자동재생 제한:** 무음·인라인 재생 및 직접 탭을 사용.
- **호버 깜빡임:** 미디어 컨테이너 경계를 고정하고 이미지와 영상 레이어를 겹쳐 전환.
- **메뉴 생성 시 영상 정보 유실:** CSV 열과 생성기 회귀시험을 함께 추가.
- **현재 미완료 변경 충돌:** 구현 전 최신 diff를 다시 확인하고 기능 관련 영역만 최소 수정.
