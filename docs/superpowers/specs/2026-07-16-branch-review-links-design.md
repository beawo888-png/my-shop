# 지점별 네이버 플레이스 리뷰 선택 화면 설계

## 목표

현재 홈페이지의 판교점 중심 고정 후기 영역을 모란본점과 판교점의 실제 네이버 플레이스 리뷰로 이동할 수 있는 지점 선택 흐름으로 변경한다. 사용자가 상단의 `고객 리뷰`를 누르면 별도 `/reviews` 화면으로 이동하고, 지점을 선택하면 해당 네이버 플레이스 방문자 리뷰 페이지를 새 탭에서 연다.

## 사용자 흐름

1. 홈페이지 상단 탐색에서 `고객 리뷰`를 누른다.
2. 같은 탭에서 `/reviews` 화면이 열린다.
3. `모란본점` 또는 `판교점` 카드에서 지점명과 주소를 확인한다.
4. `네이버 플레이스 리뷰 보기`를 누른다.
5. 선택한 지점의 네이버 방문자 리뷰 페이지가 새 탭에서 열린다.

홈페이지의 리뷰 영역은 더 이상 판교점 후기 문구 3개를 노출하지 않는다. 대신 두 지점의 리뷰를 선택할 수 있다는 안내와 `/reviews` 이동 버튼을 제공한다.

## 화면 구성

### 홈페이지 리뷰 안내 영역

- 기존 섹션 ID `reviews`는 유지해 기존 앵커와 문서 구조를 보존한다.
- 제목과 설명은 두 지점의 실제 네이버 리뷰를 확인할 수 있다는 내용으로 변경한다.
- 고정 후기 카드 목록은 제거한다.
- `지점별 고객 리뷰 보기` 내부 링크를 제공한다.

### `/reviews` 지점 선택 화면

- 기존 사이트의 로고, 색상, 글꼴, 버튼 스타일을 재사용한다.
- 화면 제목은 `지점별 고객 리뷰`로 한다.
- 모란본점 카드를 먼저, 판교점 카드를 두 번째로 표시한다.
- 각 카드에는 지점명, 영문 지역명, 주소, 네이버 플레이스 리뷰 버튼을 표시한다.
- 데스크톱에서는 카드 2개를 나란히, 모바일에서는 한 줄에 하나씩 표시한다.
- 각 외부 버튼은 `target="_blank"`와 `rel="noreferrer"`를 사용한다.

## 데이터 구조

지점 정보의 단일 원본은 계속 `lib/site-content.ts`의 `LOCATIONS`를 사용한다. `Location` 타입에 네이버 방문자 리뷰 전용 주소인 `reviewUrl`을 추가하고 두 지점에 다음 값을 연결한다.

| 지점 | Place ID | 방문자 리뷰 주소 |
| --- | --- | --- |
| 모란본점 | `1938356292` | `https://m.place.naver.com/restaurant/1938356292/review/visitor` |
| 판교점 | `1873196958` | `https://m.place.naver.com/restaurant/1873196958/review/visitor` |

네이버 리뷰 내용을 사이트에 복사, 임베드, 크롤링하거나 서버에서 중계하지 않는다. 사이트는 사용자가 선택한 지점의 공식 네이버 리뷰 화면으로 이동하는 역할만 담당한다. 자동화된 HTTP 확인은 네이버의 속도 제한으로 `429`를 반환할 수 있으므로, 링크의 Place ID와 경로 구조를 테스트하고 실제 브라우저 이동을 시각 검증한다.

## 탐색 변경

- `NAV_ITEMS`의 `고객 리뷰` 항목을 `#reviews`에서 `/reviews`로 변경한다.
- 내부 페이지 이동이므로 홈페이지 상단 탐색에서는 같은 탭을 사용한다.
- 홈페이지 본문의 `지점별 고객 리뷰 보기`도 같은 탭에서 `/reviews`로 이동한다.
- 네이버 리뷰 버튼만 새 탭에서 연다.

## 컴포넌트 경계

- `ReviewsSection`: 홈페이지의 간단한 지점별 리뷰 안내와 내부 이동 링크만 담당한다.
- `ReviewLocationCard`: 한 지점의 이름, 주소와 네이버 리뷰 외부 링크를 담당한다.
- `ReviewsPage`: 공통 헤더, 화면 소개, 두 지점 카드 목록, 홈 이동을 담당한다.
- `LOCATIONS`: 주소와 리뷰 URL을 포함한 지점 데이터의 단일 원본이다.

## 메타데이터와 접근성

- `/reviews`에 페이지 제목, 설명, canonical URL, Open Graph 메타데이터를 제공한다.
- 카드 목록과 지점 선택 영역에 의미 있는 제목 구조를 제공한다.
- 각 외부 링크의 접근성 이름에는 지점명을 포함한다.
- 키보드로 모든 내부·외부 링크에 접근할 수 있어야 한다.
- 외부 링크에는 새 탭 이동을 나타내는 문구를 버튼 텍스트에 명확히 포함한다.

## Pencil 반영

애플리케이션 코드를 변경하기 전에 프로젝트 Pencil 원본에 다음 상태를 반영한다.

- 홈페이지의 지점별 리뷰 안내 영역
- `/reviews` 데스크톱 지점 선택 화면
- `/reviews` 모바일 1열 지점 선택 화면
- 모란본점과 판교점의 명확한 순서 및 외부 리뷰 버튼

관련 없는 홈 섹션, 메뉴 화면, 예약 흐름은 변경하지 않는다.

## 오류와 외부 서비스 처리

- 네이버 플레이스가 일시적으로 응답하지 않더라도 사이트 자체 화면은 정상 렌더링한다.
- 외부 리뷰 페이지의 로딩 실패, 로그인 요구, 속도 제한은 네이버가 처리한다.
- 사이트에서는 외부 리뷰 데이터를 미리 가져오지 않으므로 네이버 장애가 홈페이지 렌더링을 방해하지 않는다.

## 검증

- 홈페이지 상단의 `고객 리뷰`가 `/reviews`를 가리키는지 확인한다.
- 홈페이지 리뷰 섹션에 내부 `/reviews` 링크가 있고 기존 고정 후기 목록이 제거됐는지 확인한다.
- `/reviews`가 모란본점, 판교점 순서로 두 카드를 렌더링하는지 확인한다.
- 각 카드가 정확한 Place ID와 `/review/visitor` 경로를 사용하는지 확인한다.
- 외부 링크에 `target="_blank"`와 `rel="noreferrer"`가 있는지 확인한다.
- 데스크톱 2열과 모바일 1열 반응형 배치를 확인한다.
- 메타데이터, 접근성 이름, 홈 이동 링크를 확인한다.
- 전체 테스트, ESLint, TypeScript 및 프로덕션 빌드를 실행한다.
- 실제 브라우저에서 홈페이지 → `/reviews` → 각 네이버 리뷰 링크 흐름을 확인한다.

## 범위 제외

- 네이버 리뷰 본문 또는 작성자 정보 복사
- 네이버 리뷰 크롤링, 임베드 또는 API 연동
- 별점 통계의 자동 집계
- 사이트 내부 리뷰 작성 기능
- 지점 정보나 예약 링크 변경
