# 지점 카드 라벨 정렬과 길찾기 버튼 스타일 설계

## 목표

지점 카드의 정보 라벨을 짧고 일정하게 정렬하고, 네이버·Google 길찾기 버튼을 참고 이미지처럼 한 줄에 나란히 배치한다. 왕징의 적색 시각 체계는 유지하면서 Google 버튼은 검정 배경과 흰색 글자로 분명히 구분한다.

## 정보 라벨

상세 정보의 표시 순서와 라벨은 다음과 같다.

1. `주소`
2. `가까운 역`
3. `전화번호`
4. `주차장`

기존 `주차장 이용방법`에서 `이용방법`을 삭제한다. 네 라벨은 같은 글자 크기, 굵기, 자간, 줄 높이와 고정 열 너비를 사용한다. 라벨은 불필요한 수동 공백 없이 왼쪽 정렬하고, 모든 값은 같은 세로선에서 시작한다.

데스크톱과 모바일 모두 라벨 열이 가장 긴 `가까운 역`과 `전화번호`를 한 줄로 표시할 수 있는 너비를 확보한다. 주차 안내 내용은 남은 값 영역에서 자연스럽게 줄바꿈한다.

## 길찾기 버튼

- 버튼 영역은 동일한 너비의 2열 그리드로 구성한다.
- 왼쪽은 `네이버 길찾기`, 오른쪽은 `구글 길찾기` 순서를 유지한다.
- 두 버튼은 같은 높이와 내부 정렬을 사용한다.
- 모서리는 `10px` 반경을 사용해 네모보다 부드럽고 완전한 캡슐보다 절제된 형태로 만든다.
- 네이버 버튼은 기존 왕징 적색 배경과 종이색 글자를 유지한다.
- Google 버튼은 `--ink` 검정 배경과 `--paper` 흰색 글자를 사용한다.
- Google 버튼의 hover 상태는 검정 계열에서 적색으로 전환해 현재 사이트의 상호작용 언어를 따른다.
- 모바일에서도 두 버튼을 한 줄에 유지하며 카드 폭을 넘지 않도록 각 열을 `minmax(0, 1fr)`로 설정한다.

## 컴포넌트와 스타일 경계

- `components/home/location-card.tsx`에서는 주차 라벨 문구만 `주차장`으로 변경한다.
- 기존 지점 데이터와 네이버·Google URL, 접근성 이름, 새 탭 보안 속성은 변경하지 않는다.
- `app/globals.css`에서 상세 정보 라벨 규격, 버튼 2열 배치, 모서리 반경, Google 버튼 색상을 관리한다.
- 별도 아이콘이나 외부 패키지는 추가하지 않는다.

## Pencil 선행 반영

애플리케이션 코드보다 먼저 `초안`의 `F9bKD` 데스크톱 지점 카드 상세 스케치와 `d8YZpT` 모바일 상세 스케치를 수정한다. 두 스케치에서 주차 라벨을 줄이고 네 라벨의 기준선을 맞추며 버튼을 한 줄의 동일 너비로 배치한다. Google 버튼은 검정 배경과 흰색 글자로 표시하고 두 버튼 모두 10px 수준의 모서리 반경을 사용한다.

## 반응형·접근성

- 데스크톱 2열 지점 카드와 모바일 1열 지점 카드 구조는 유지한다.
- 모바일에서 각 버튼은 최소 48px 높이를 유지한다.
- 버튼의 보이는 문구와 지점명이 포함된 기존 `aria-label`을 유지한다.
- 외부 링크의 `target="_blank"`와 `rel="noreferrer"`를 유지한다.
- 긴 판교점 주차 문구는 카드 안에서 줄바꿈하며 가로 스크롤을 만들지 않는다.

## 테스트와 완료 기준

- 구조 테스트에서 `주차장` 라벨을 확인하고 `주차장 이용방법`이 남지 않았는지 검증한다.
- CSS 구조 테스트에서 라벨의 고정 열, 공통 자간, 버튼 2열 그리드, 10px 모서리 반경, Google 버튼의 검정 배경과 흰색 글자를 확인한다.
- 기존 네이버·Google 링크와 접근성 검증은 그대로 통과해야 한다.
- 전체 테스트, ESLint, 프로덕션 빌드를 실행한다.
- 데스크톱과 390px 모바일 화면에서 네 라벨의 시작선, 두 버튼의 한 줄 배치, 긴 주차 안내의 줄바꿈, 가로 넘침 부재를 시각적으로 확인한다.
- 기존 Vercel 프로젝트 배포는 구현 검증이 끝난 뒤 사용자의 별도 요청 또는 기존 배포 흐름 승인에 따라 진행한다.
