# 왕징 두 지점 안내 섹션 설계

## 목표

현재 판교점 한 곳만 보여주는 지점 안내 섹션을 모란본점과 판교점 두 곳을 함께 비교할 수 있는 카드형 섹션으로 교체한다. 사용자가 제공한 육즙관리소 참고 화면의 정보 구조를 따르되, 왕징 홈페이지의 크림·적색·먹색·금색 시각 체계는 유지한다.

## 콘텐츠 구조

상단 메뉴의 `지점 안내`는 `#location`으로 이동하며, 이동한 섹션에는 두 지점이 한 화면에 함께 표시되어야 한다. 섹션 상단에는 영문 레이블 `LOCATIONS`, 제목 `두 곳에서 만나요`, 모란본점과 판교점의 네이버 플레이스로 바로 이동하는 캡슐 링크 두 개를 표시한다. 그 아래에는 모란본점 카드를 왼쪽, 판교점 카드를 오른쪽에 두는 2열 구조를 사용한다.

기존 판교점 단일 이미지·설명 블록과 그 안의 예약/지도/전화 버튼 묶음은 이 두 지점 카드로 교체한다. 예약 기능은 헤더, 히어로, 예약 배너 등 기존 사이트의 다른 예약 동선에 그대로 남는다.

각 지점 카드는 다음 정보를 같은 순서로 제공한다.

1. 대표 이미지
2. 영문 지역 레이블과 한글 지점명
3. 주소
4. 가까운 역과 거리
5. 전화번호 링크
6. 네이버 플레이스 버튼

## 컴포넌트와 데이터 경계

- `lib/site-content.ts`에 `Location` 타입과 두 지점 데이터 배열을 둔다. 지점명, 이미지, 주소, 교통, 전화, 플레이스 URL을 한 객체로 관리한다.
- `components/home/location-card.tsx`는 지점 객체 하나를 받아 카드 한 장을 렌더링한다.
- `components/home/location-section.tsx`는 제목, 지점 바로가기, 두 카드의 그리드만 담당한다.
- 기존 내비게이션의 `#location` 링크는 그대로 유지한다.

이 분리는 지점 정보 수정과 카드 표시 로직을 분리하며, 향후 지점 추가 시 데이터 배열에 항목을 추가하는 방식으로 확장할 수 있게 한다.

## 시각 디자인

- 섹션 배경은 기존 `--cream`을 유지한다.
- 섹션 제목에는 기존 명조 계열 서체와 먹색을 사용한다.
- 지점 바로가기는 참고 화면처럼 둥근 캡슐 링크로 만들되 왕징의 적색 점과 크림·라인 색을 사용하고, 클릭하면 해당 지점의 네이버 플레이스를 새 탭에서 연다.
- 카드는 기존 `--paper` 배경과 가는 테두리, 작은 모서리 반경을 사용한다.
- 대표 이미지는 동일한 가로세로 비율로 잘라 카드 높이를 맞추며, 모란본점 사진의 간판과 출입구가 중심에 오도록 `object-position`을 지정한다.
- 네이버 플레이스 버튼은 기존 기본 버튼 스타일을 재사용한다.

## 반응형 동작

- 768px 이상에서는 카드 두 장을 같은 너비의 2열로 표시한다.
- 767px 이하에서는 카드 한 장씩 세로로 쌓는다.
- 지점 바로가기 링크는 좁은 화면에서 줄바꿈된다.
- 이미지 높이는 모바일에서 줄여 본문 정보가 지나치게 아래로 밀리지 않도록 한다.
- 전화번호와 플레이스 버튼의 터치 영역은 최소 48px을 유지한다.

## 링크와 접근성

- 상단 모란본점 캡슐 링크는 `LOCATIONS`의 모란본점 `mapUrl`을, 판교점 캡슐 링크는 판교점 `mapUrl`을 사용한다.
- 두 캡슐 링크는 `target="_blank"`와 `rel="noreferrer"`를 지정해 새 탭에서 안전하게 연다.
- 각 카드의 네이버 플레이스 버튼은 사용자가 제공한 외부 URL을 새 탭에서 열고 `rel="noreferrer"`를 지정한다.
- 전화번호는 `tel:` 링크로 제공한다.
- 각 대표 이미지는 지점명과 외관을 설명하는 대체 텍스트를 가진다.
- 제목·목록·카드의 의미가 스크린 리더에 전달되도록 섹션과 목록 구조를 사용한다.

## 오류 처리

- 이미지 크기를 명시해 로딩 중 레이아웃 이동을 막는다.
- 이미지가 로드되지 않아도 지점명, 주소, 전화, 네이버 플레이스 링크는 그대로 사용할 수 있다.
- 외부 플레이스 링크가 변경되더라도 다른 지점 카드와 홈페이지 내비게이션에는 영향을 주지 않는다.

## 테스트와 완료 기준

- 콘텐츠 테스트에서 두 지점 데이터, 전화번호, 주소, 플레이스 ID를 확인한다.
- 구조 테스트에서 `LocationSection`이 두 개의 지점 카드를 렌더링하고 캡슐 링크가 각 지점의 `mapUrl`, `target="_blank"`, `rel="noreferrer"`를 사용하는지 확인한다.
- 자산 테스트에서 모란본점 대표 이미지가 프로젝트에 존재하고 비어 있지 않은지 확인한다.
- 기존 전체 테스트, ESLint, Next.js 프로덕션 빌드를 실행한다.
- 데스크톱과 모바일에서 2열/1열 전환, 이미지 잘림, 링크 가독성, 기존 색상 유지 여부를 시각적으로 확인한다.
- 공개 배포는 사용자가 별도로 요청할 때만 기존 Vercel 프로젝트에 진행하며 새 프로젝트는 생성하지 않는다.
