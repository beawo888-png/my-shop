# 왕징 홈페이지 다국어 전환 설계

## 배경

현재 공용 헤더 우측에는 `네이버 예약` 드롭다운이 있고, 홈페이지 본문은 한국어로만 제공된다. 사용자는 육즙관리소처럼 우측 상단에 현재 언어를 표시하고, 버튼을 누르면 영어·중국어 간체·일본어를 선택할 수 있기를 원한다.

승인된 범위는 홈페이지 번역만이다. 전체 메뉴(`/menu` 및 하위 카테고리)와 리뷰 페이지(`/reviews`)는 한국어로 유지한다.

## 목표

- 한국어 `/`, 영어 `/en`, 중국어 간체 `/zh`, 일본어 `/ja` 홈페이지를 제공한다.
- 데스크톱과 태블릿에서 우측 상단 `네이버 예약`을 현재 언어 선택 버튼으로 교체한다.
- 모바일에서는 햄버거 메뉴 안에 언어 선택 목록을 제공한다.
- 홈페이지의 모든 사용자 표시 문구를 선택한 언어로 전환한다.
- 언어를 전환할 때 현재 보고 있던 홈페이지 앵커(`#story`, `#group`, `#location`, `#faq` 등)를 유지한다.
- 현재 브랜드 색상, 로고, 반응형 레이아웃과 접근성을 유지한다.

## 비목표

- `/menu`, `/menu/[category]`, `/reviews`, 관리자 화면은 번역하지 않는다.
- 외부 자동 번역 위젯이나 브라우저 번역 기능을 삽입하지 않는다.
- 지점명, 주소, 전화번호, 가격, 인원, 시간, 온도 등 사업 사실을 변경하지 않는다.
- 새 Vercel 프로젝트를 만들거나 별도 배포 경로를 추가하지 않는다.

## 언어와 경로

| 언어 | 내부 코드 | 홈페이지 경로 | 선택기 표시 |
| --- | --- | --- | --- |
| 한국어 | `ko` | `/` | `한국어` |
| 영어 | `en` | `/en` | `English` |
| 중국어 간체 | `zh` | `/zh` | `简体中文` |
| 일본어 | `ja` | `/ja` | `日本語` |

한국어는 기존 루트 주소를 유지한다. 외국어 경로는 정적 생성하며, 지원하지 않는 언어 코드는 404로 처리한다.

## 사용자 흐름

### 데스크톱·태블릿

1. 헤더 우측 버튼에 현재 언어가 표시된다.
2. 버튼을 누르면 네 언어가 세로 목록으로 열린다.
3. 현재 언어에는 선택 상태를 시각적·접근성 상태로 표시한다.
4. 다른 언어를 선택하면 해당 언어 홈페이지로 이동한다.
5. 현재 URL에 홈페이지 앵커가 있으면 새 언어 경로에도 같은 앵커를 붙인다.
6. 바깥을 클릭하거나 `Escape`를 누르면 목록이 닫힌다.

### 모바일

- 기존 햄버거 버튼은 유지한다.
- 모바일 메뉴 안에 `언어 / Language` 영역과 네 언어 링크를 추가한다.
- 기존 모바일 지점별 네이버 예약 링크는 그대로 유지한다.
- 언어를 선택하면 모바일 메뉴를 닫고 해당 언어 홈페이지로 이동한다.

## 헤더와 예약 동작

- 공용 헤더의 데스크톱·태블릿 `네이버 예약` 버튼만 언어 선택기로 교체한다.
- 홈페이지 하단 예약 배너와 모바일 하단 예약 바는 유지한다.
- 모바일 햄버거 메뉴 안의 모란본점·판교점 네이버 예약 링크도 유지한다.
- `/menu`와 `/reviews`의 공용 헤더에도 현재 언어가 `한국어`로 표시된다. 다른 언어를 선택하면 해당 언어의 홈페이지로 이동한다.

## 번역 범위

각 외국어 홈페이지는 다음 문구를 모두 번역한다.

- 헤더 내비게이션과 접근성 레이블
- 히어로 제목·설명
- 대표 메뉴 섹션 제목·설명·버튼 레이블
- 브랜드 스토리 전체 문단
- 네 가지 약속 제목·설명·항목
- 단체 모임 소개, 추천 모임, 지점별 설명과 레이블
- 고객 리뷰 섹션 문구
- 지점 안내 제목, 주소·역·전화·주차 레이블과 버튼 레이블
- FAQ 여섯 질문과 답변
- 예약 배너와 모바일 예약 바
- 푸터 제목·지점·내비게이션·안내 문구
- 페이지 제목, 설명, Open Graph 및 언어 대체 링크 메타데이터

브랜드 로고 이미지는 모든 언어에서 동일하게 사용한다. `왕징양다리양꼬치` 텍스트는 각 언어에서 자연스러운 브랜드 표기를 사용하되, 주소·전화번호·가격·수량·온도·시간과 외부 링크는 한국어 원본 데이터와 정확히 동일해야 한다.

외국어 홈페이지에서 `대표 메뉴` 링크는 번역된 짧은 레이블을 사용하되 한국어 `/menu`를 새 탭으로 열고, 고객 리뷰 버튼은 번역된 레이블로 한국어 `/reviews`로 이동한다. 메뉴·리뷰 대상 페이지 자체에는 다국어처럼 보이는 문구를 추가하지 않는다.

## 구성과 데이터 흐름

### 번역 데이터

- `Locale`은 `ko | en | zh | ja`의 제한된 타입으로 정의한다.
- 언어 이름, 경로, HTML 언어 코드와 홈페이지 전체 문구를 하나의 타입 안전한 번역 데이터 모듈에서 관리한다.
- 모든 언어 객체는 동일한 섹션 키와 동일한 배열 길이를 가져야 한다.
- 지점의 주소·전화·지도·예약 URL 같은 사실 데이터는 기존 `lib/site-content.ts`를 단일 출처로 유지하고, 번역 데이터에는 표시 레이블과 설명만 둔다.
- FAQ의 ID와 강조 구간 구조는 모든 언어에서 동일하게 유지한다.

### 페이지 구성

- 기존 `app/page.tsx`는 한국어 로케일을 전달해 공용 홈페이지 렌더러를 사용한다.
- `app/[locale]/page.tsx`는 `en`, `zh`, `ja`만 정적 생성하고 같은 공용 홈페이지 렌더러를 사용한다.
- 기존 홈페이지 섹션 컴포넌트는 레이아웃을 소유하고, 번역된 문구와 레이블을 props로 받는다.
- 외국어 본문 최상위 컨테이너에 올바른 `lang` 속성을 적용해 루트 문서 언어와 별개로 보조기기가 언어를 인식하도록 한다.

### 언어 선택기

- 헤더는 현재 `locale`을 받아 현재 언어 레이블과 네 개 언어 링크를 렌더링한다.
- 링크는 JavaScript가 없어도 각 언어 루트로 이동한다.
- 클라이언트 동작이 가능하면 현재 홈페이지 앵커를 읽어 대상 경로에 보존한다.
- 버튼은 `aria-haspopup`, `aria-expanded`, `aria-controls`를 제공하고 목록은 명시적인 내비게이션 레이블을 가진다.
- 현재 언어 링크는 `aria-current="page"`로 표시한다.

## SEO와 검색 노출

- 각 언어 페이지는 번역된 title과 description 및 자기 자신을 가리키는 canonical을 가진다.
- 모든 홈페이지는 `ko`, `en`, `zh-CN`, `ja`, `x-default` 대체 언어 링크를 제공한다.
- 사이트맵에 네 홈페이지 경로를 추가한다.
- 외국어 페이지의 구조화 데이터는 지점명·주소·전화·URL 사실을 기존 데이터에서 재사용하고, 설명만 해당 언어로 제공한다.

## 시각 설계

- 기존 검붉은색·크림색·금색 토큰과 헤더 높이를 유지한다.
- 언어 버튼은 현재 예약 버튼과 같은 48px 최소 높이와 동일한 위치를 사용한다. 배경은 투명한 검정, 테두리와 글자는 크림색으로 표시하고 hover·focus 시 금색을 사용해 붉은 예약 CTA와 구분한다.
- 드롭다운은 기존 예약 드롭다운의 폭, 테두리, 그림자와 포커스 스타일을 재사용한다.
- 태블릿 두 줄 헤더에서도 언어 버튼은 첫째 줄 우측, 내비게이션은 둘째 줄에 유지한다.
- 영어의 긴 문구와 일본어·중국어 줄바꿈 때문에 카드나 버튼이 잘리지 않도록 고정 텍스트 높이를 두지 않는다.
- 구현 전 Pencil 파일 `초안`에 데스크톱 닫힘·열림 상태, 태블릿 배치, 모바일 메뉴 언어 영역을 추가한다.

## 오류와 예외 처리

- 지원하지 않는 로케일은 한국어로 조용히 대체하지 않고 404로 처리한다.
- 누락된 번역 키는 타입 검사와 테스트에서 실패해야 하며 런타임에 한국어·빈 문자열로 숨기지 않는다.
- 외부 예약·지도 링크와 전화 링크는 언어와 무관하게 기존 URL을 그대로 사용한다.
- 알 수 없는 해시는 언어 전환 시 버리고, 승인된 홈페이지 섹션 해시만 보존한다.

## 테스트와 검증

- 번역 데이터에 네 언어와 동일한 섹션 구조가 있는지 검사한다.
- 각 언어에 여섯 FAQ와 두 지점이 있으며 숫자·가격·전화·URL 같은 필수 사실이 보존되는지 검사한다.
- `/`, `/en`, `/zh`, `/ja`가 정적으로 빌드되는지 확인한다.
- 언어 버튼 열기·닫기, 바깥 클릭, `Escape`, `aria-expanded`, `aria-current`와 앵커 보존을 확인한다.
- 1440px, 910px, 390px에서 긴 번역 문구, 드롭다운, 모바일 메뉴, 가로 넘침을 시각 검증한다.
- 기존 한국어 홈페이지, `/menu`, `/reviews`, FAQ, 예약 링크 테스트를 모두 다시 실행한다.
- 프로덕션 빌드 후 GitHub `main`에 푸시하고 기존 Vercel 프로젝트 `my-shop-39ab`의 자동 배포와 네 언어 경로를 확인한다.

## 완료 기준

- 우측 상단에 현재 언어가 표시되고 네 언어 선택이 실제로 작동한다.
- `/en`, `/zh`, `/ja`에서 홈페이지의 모든 사용자 표시 문구가 선택 언어로 보인다.
- 모바일 메뉴에서도 언어를 선택할 수 있다.
- 한국어 메뉴·리뷰 페이지와 모든 지점·예약·지도 링크가 손상되지 않는다.
- 접근성, 반응형 화면, 테스트, 빌드 및 기존 Vercel 자동 배포가 모두 검증된다.
