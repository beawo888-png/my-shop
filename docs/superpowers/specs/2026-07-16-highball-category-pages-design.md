# 하이볼 이미지 및 카테고리별 메뉴 화면 설계

## 목표

현재 모든 메뉴 카테고리를 한 페이지에 세로로 나열하고 앵커 링크로 이동하는 구조를 카테고리별 독립 화면 구조로 변경한다. 주류·하이볼 화면에서는 고량주와 맥주 다음에 하이볼 전용 구역을 배치하고, 사용자가 제공한 하이볼 이미지 6장을 상품별로 정확히 연결한다. 기존 상품 가격, 이름, 설명은 변경하지 않는다.

## 확정된 사용자 경험

- `/menu` 진입 시 첫 카테고리인 `/menu/signature-lamb-leg`로 이동한다.
- 메뉴 화면 상단에는 모든 카테고리 링크를 유지한다.
- 카테고리를 누르면 한 페이지 안에서 스크롤하지 않고 해당 카테고리의 독립 주소로 이동한다.
- 각 카테고리 화면에는 선택한 카테고리의 상품만 표시한다.
- 현재 카테고리는 상단 탐색에서 시각적·접근성 상태로 구분한다.
- 존재하지 않는 카테고리 주소는 404 화면으로 처리한다.

## 카테고리 경로

| 카테고리 | 경로 |
| --- | --- |
| 시그니처 양다리 | `/menu/signature-lamb-leg` |
| 양꼬치·세트메뉴 | `/menu/lamb-skewers` |
| 중국요리·탕 | `/menu/chinese-dishes` |
| 식사·면·디저트 | `/menu/meals` |
| 주류·하이볼 | `/menu/drinks` |

## 화면 구조

공통 메뉴 레이아웃은 기존 로고, 홈 이동, 소개 영역, 카테고리 탐색, 예약·네이버 플레이스 링크를 유지한다. 동적 카테고리 화면은 경로에서 카테고리 ID를 받아 `PANGYO_MENU_GROUPS`의 단일 그룹만 조회하고 렌더링한다. 구조화 데이터도 현재 화면에 표시되는 카테고리를 기준으로 생성해 화면과 데이터가 일치하도록 한다.

기존 `#menu-*` 앵커 링크와 모든 그룹을 순회해 한 문서에 렌더링하는 구조는 제거한다. 카테고리 탐색은 Next.js 내부 링크를 사용하며 현재 카테고리에 `aria-current="page"`를 제공한다.

## 주류·하이볼 구성

`/menu/drinks`에서는 기존 고량주 및 맥주 9종을 먼저 표시한다. 그 다음 별도 제목을 가진 하이볼 구역에 다음 6종을 배치한다.

1. 산토리하이볼
2. 제임슨하이볼
3. 짐빔하이볼
4. 커티삭하이볼
5. 봄베이하이볼
6. 연태하이볼

데스크톱에서는 3열 2행, 태블릿에서는 2열, 모바일에서는 1열로 표시한다. 상품 카드의 기존 `contain` 이미지 맞춤 방식은 유지한다.

## 이미지 연결

사용자가 제공한 원본 PNG를 재압축하거나 자르지 않고 `public/images/wangjing/menu/`에 영문 파일명으로 복사한다.

| 상품 | 파일명 |
| --- | --- |
| 산토리하이볼 | `suntory-highball.png` |
| 제임슨하이볼 | `jameson-highball.png` |
| 짐빔하이볼 | `jim-beam-highball.png` |
| 커티삭하이볼 | `cutty-sark-highball.png` |
| 봄베이하이볼 | `bombay-highball.png` |
| 연태하이볼 | `yantai-highball.png` |

기존 `cutty-sark-highball.jpg`는 새 PNG로 대체된 메뉴 데이터에서 더 이상 참조하지 않는다. 다른 메뉴 이미지와 대체 이미지 동작에는 영향을 주지 않는다.

## 데이터와 가격 보존

메뉴의 단일 원본은 계속 `lib/menu-content.ts`로 유지한다. 화면 배치를 위해 주류 그룹 안에서 일반 주류와 하이볼을 구분할 수 있는 명시적인 데이터 속성 또는 하위 구역을 추가하되, 다음 가격은 그대로 보존한다.

| 상품 | 가격 |
| --- | --- |
| 커티삭하이볼 | 6,000원 |
| 산토리하이볼 | 8,000원 |
| 봄베이하이볼 | 8,000원 |
| 짐빔하이볼 | 7,000원 |
| 제임슨하이볼 | 8,000원 |
| 연태하이볼 | 7,000원 |

하이볼 구역의 표시 순서는 위의 확정된 6종 순서를 따르지만, 상품별 가격·이름·설명은 기존 값을 사용한다. 전체 메뉴 수 44개도 유지한다.

## Pencil 반영

애플리케이션 코드 변경 전에 프로젝트 Pencil 원본에 다음을 반영한다.

- 한 화면에 한 카테고리만 표시되는 구조
- 독립 화면으로 이동하는 상단 카테고리 탐색
- 현재 카테고리 상태
- 주류·하이볼 화면 맨 아래의 하이볼 3열 2행 구역
- 모바일의 하이볼 1열 배치

기존 시각 언어와 카드 스타일은 유지하며 관련 없는 홈 화면이나 브랜드 스타일은 변경하지 않는다.

## 오류 처리

- 알려지지 않은 카테고리 ID는 Next.js의 `notFound()`로 처리한다.
- 상품 이미지 로드 실패 시 기존 그룹 대체 이미지 동작을 유지한다.
- `/menu`는 항상 첫 카테고리 경로로 이동해 빈 화면이나 전체 세로 목록을 표시하지 않는다.

## 검증

- `/menu`가 `/menu/signature-lamb-leg`로 이동하는지 확인한다.
- 5개 카테고리 경로가 각각 해당 그룹만 렌더링하는지 확인한다.
- 상단 링크가 앵커가 아닌 독립 경로이며 현재 화면에 `aria-current`가 있는지 확인한다.
- 잘못된 카테고리 경로가 404로 처리되는지 확인한다.
- 주류 화면에서 고량주·맥주가 먼저, 하이볼 6종이 마지막에 표시되는지 확인한다.
- 하이볼 이미지 6개가 존재하고 각 상품에 정확히 연결되는지 확인한다.
- 하이볼 가격, 전체 상품 수 44개, 구조화 데이터가 유지되는지 확인한다.
- 데스크톱 3열, 태블릿 2열, 모바일 1열 반응형 규칙을 확인한다.
- 프로젝트 테스트와 정적 검사를 모두 실행한다.

## 범위 제외

- 메뉴 상품 추가·삭제 및 가격 변경
- 하이볼 원본 이미지 보정, 자르기 또는 형식 변환
- 홈 화면의 대표 메뉴 카드 변경
- 예약 및 네이버 플레이스 외부 링크 변경
- 브랜드 전반의 스타일 개편
