# 판교왕징 반응형 홈페이지 설계

## 1. 목표

현재 Next.js 기본 시작 화면을 판교왕징의 실제 운영 정보를 담은 반응형 원페이지 홈페이지로 교체한다. 방문자가 음식과 매장 정보를 신뢰할 수 있게 확인한 뒤 네이버 예약 페이지로 이동하는 것이 최우선 목표다.

성공 기준은 다음과 같다.

- 데스크톱, 태블릿, 모바일에서 콘텐츠가 겹치거나 잘리지 않는다.
- 상단, 첫 화면, 지점 안내, 마지막 예약 영역, 모바일 고정 바에서 네이버 예약으로 이동할 수 있다.
- 전화 버튼은 모바일 전화 앱으로 연결되고 길찾기 버튼은 판교점 주소를 네이버 지도에서 연다.
- 제공된 실제 매장 사진과 음식 사진이 원격 임시 이미지 없이 표시된다.
- Vercel 운영 빌드와 공개 배포가 성공한다.

## 2. 범위

이번 작업은 한국어 단일 원페이지를 구현한다. 별도 데이터베이스, 관리자 화면, 회원 기능, 결제, 온라인 주문, 영어 페이지는 포함하지 않는다. 상단의 `KO | EN` 표시는 실제 영어 페이지가 없으므로 제거한다.

운영 정보는 사용자가 실제 정보라고 확인한 현재 초안의 내용을 그대로 사용한다.

- 매장명: 판교왕징
- 주소: 경기 성남시 분당구 대왕판교로606번길 10, 205호·206호
- 교통: 판교역 4번 출구에서 약 266m
- 전화: 0507-1313-5688
- 네이버 예약: https://booking.naver.com/booking/6/bizes/970819
- 대표 메뉴, 가격, 리뷰 수치와 문구: `초안-exports/home-desktop.html` 기준

## 3. 디자인 기준과 원본 정합성

시각 기준은 `초안-exports/home-desktop.html`의 판교왕징 데스크톱 초안이다. 짙은 흑갈색, 아이보리, 금색, 짙은 적색을 사용해 중국 양고기 다이닝의 불향과 모임 장소의 품격을 표현한다.

현재 Pencil 원본 `초안`은 800×600 빈 프레임만 포함하고 있어 내보낸 데스크톱 초안과 불일치한다. 프로젝트 규칙에 따라 애플리케이션 코드를 수정하기 전에 Pencil 원본을 승인된 구조에 맞춰 갱신하고, 이후 구현 결과와 정합성을 유지한다.

## 4. 정보 구조

페이지는 다음 순서로 구성한다.

1. 상단 내비게이션
2. 대표 이미지와 소개 문구
3. 방문자 리뷰·판교역 거리·주차·단체석 신뢰 정보
4. 대표 메뉴 3종
5. 왕징 이야기
6. 단체 모임 안내
7. 고객 리뷰
8. 판교점 정보와 외관
9. 마지막 예약 유도 영역
10. 푸터

상단 메뉴는 `대표 메뉴`, `왕징 이야기`, `단체 모임`, `고객 리뷰`, `지점 안내` 영역으로 이동한다. 데스크톱에서는 일반 내비게이션을 사용하고, 모바일에서는 메뉴 버튼으로 여는 접이식 내비게이션을 사용한다.

## 5. 주요 화면과 컴포넌트

### 상단 내비게이션

`王京 판교왕징` 워드마크, 페이지 내부 이동 메뉴, 네이버 예약 버튼으로 구성한다. 스크롤 중에도 예약 행동을 찾기 쉽도록 상단을 고정한다.

### 대표 영역

불 위에서 조리 중인 양꼬치 가로 사진을 사용한다. 어두운 오버레이 위에 다음 정보를 표시한다.

- `PANGYO · CHINESE LAMB DINING`
- `불향으로 완성한 양고기, 중요한 자리를 위한 왕징`
- 매장 소개 문구
- 주요 네이버 예약 버튼
- 단체 모임 문의 버튼

대표 영역 하단에는 방문자 리뷰 수, 판교역 접근성, 주차·단체석 정보를 배치한다.

### 대표 메뉴

양꼬치, 양갈비살꼬치, 꿔바로우를 3개 카드로 보여준다. 각 카드에는 실제 음식 사진, 메뉴명, 가격, 한 줄 설명을 표시한다. 데스크톱에서는 3열, 태블릿에서는 2열로 배치하되 마지막 카드는 두 열을 차지하며, 모바일에서는 1열로 전환한다.

### 왕징 이야기와 단체 모임

통양다리와 한 상 차림 사진으로 불향과 메뉴 다양성을 표현한다. 단체 모임 영역에는 실제 매장 내부와 긴 좌석 사진을 사용하고, 좌석·주차·예약 가능 정보를 짧은 체크 목록으로 제공한다. 행동 버튼은 전화 문의와 네이버 예약으로 연결한다.

### 고객 리뷰

초안의 리뷰 문구와 분류를 카드 3개로 표시한다. 리뷰가 실제 운영 정보라는 사용자 확인을 전제로 현재 수치와 문구를 유지한다. 리뷰 카드에는 과도한 장식 없이 읽기 쉬운 본문, 분류, 날짜를 표시한다.

### 지점 안내

판교점 주소, 교통, 전화번호, 외관 사진을 표시한다. 네이버 예약, 길찾기, 전화 버튼을 함께 제공한다. 지도 SDK나 API 키가 필요한 내장 지도는 이번 범위에서 제외하고 네이버 지도 검색 링크를 사용한다.

### 마지막 예약 영역과 모바일 고정 바

불향이 강조된 음식 사진 위에 예약 문구와 네이버 예약 버튼을 배치한다. 모바일에서는 화면 하단에 예약 버튼을 고정하고, 콘텐츠가 가려지지 않도록 페이지 하단 여백을 확보한다.

## 6. 이미지 사용 계획

사용자가 제공한 13개 이미지를 프로젝트의 `public/images/wangjing/` 아래에 의미 있는 영문 파일명으로 복사한다. 원본은 변경하지 않고 웹 표시용 파일만 프로젝트 내부에서 관리한다.

- 대표 영역: 불 위의 양꼬치 가로 사진
- 대표 메뉴: 양꼬치, 양갈비, 꿔바로우 음식 사진
- 왕징 이야기: 통양다리와 전체 상차림 사진
- 단체 모임: 실제 매장 내부와 긴 좌석 사진
- 지점 안내: 실제 외부 간판 사진
- 마지막 예약: 불향이 강조된 음식 사진 재사용

Next.js 이미지 최적화를 사용하고 각 용도에 맞는 `sizes`, 비율, 대체 텍스트를 지정한다. 사진이 없는 영역에 외부 Unsplash 이미지를 사용하지 않는다.

## 7. 기술 구조

페이지는 Next.js App Router의 정적 콘텐츠 중심 서버 컴포넌트로 구현한다. 불필요한 클라이언트 JavaScript를 피하고, 모바일 메뉴처럼 상태가 필요한 작은 영역만 클라이언트 컴포넌트로 분리한다.

주요 단위는 다음과 같다.

- `SiteHeader`: 브랜드, 내부 이동, 예약 행동
- `HeroSection`: 대표 이미지, 소개, 핵심 CTA, 신뢰 정보
- `SignatureMenuSection`: 메뉴 데이터와 카드 목록
- `StorySection`: 브랜드 이야기
- `GroupDiningSection`: 단체석과 문의 행동
- `ReviewsSection`: 리뷰 카드
- `LocationSection`: 주소, 전화, 외관, 외부 링크
- `ReservationBanner`: 마지막 예약 유도
- `MobileBookingBar`: 모바일 고정 예약 행동
- `SiteFooter`: 매장 정보와 보조 링크

메뉴, 리뷰, 신뢰 정보는 컴포넌트에 흩어 쓰지 않고 타입이 있는 데이터 배열로 관리한다. 외부 링크는 한 곳의 상수로 관리해 변경 시 누락을 방지한다.

## 8. 동작과 데이터 흐름

이 페이지는 입력 폼이나 서버 저장이 없는 읽기 중심 사이트다. 사용자 행동은 다음 경로로만 외부 이동한다.

- 네이버 예약 버튼 → 제공된 네이버 예약 URL
- 전화 버튼 → `tel:050713135688`
- 길찾기 버튼 → 주소가 포함된 네이버 지도 검색 URL
- 상단 메뉴 → 동일 페이지의 섹션 앵커

외부 링크는 새 탭에서 열고 안전한 `rel` 속성을 사용한다. 전화 링크는 현재 탭에서 시스템 전화 기능을 호출한다.

## 9. 반응형과 접근성

- 데스크톱 기준 최대 콘텐츠 너비를 두고 큰 사진과 넉넉한 여백을 유지한다.
- 모바일은 1열 구조로 바꾸되 제목과 본문 글자 크기를 과도하게 줄이지 않는다.
- 모든 클릭·터치 영역은 최소 48×48px을 확보한다.
- 버튼과 링크는 키보드 포커스가 명확히 보이게 한다.
- 장식용 사진과 정보성 사진을 구분해 적절한 대체 텍스트를 제공한다.
- 색상만으로 상태나 행동을 구분하지 않는다.
- `prefers-reduced-motion`에서는 부드러운 스크롤과 장식 애니메이션을 줄인다.
- 모바일 고정 바가 본문과 푸터를 가리지 않게 안전 여백을 둔다.

## 10. 오류 처리와 안전장치

- 사진은 프로젝트 내부에서 제공해 외부 이미지 만료와 핫링크 실패를 방지한다.
- 링크 상수에 유효한 URL 또는 전화번호만 사용한다.
- 내장 지도 실패 가능성을 제거하기 위해 외부 지도 링크를 사용한다.
- 실제 운영 정보 변경은 데이터 상수에서 한 번에 수정할 수 있게 한다.
- 영문 페이지가 없는 상태에서 작동하지 않는 언어 전환 UI를 노출하지 않는다.

## 11. 검증 계획

### 자동 검증

- `npm run lint`
- `npm run build`
- Node 기본 테스트 러너로 핵심 링크 상수, 섹션 ID, 운영 정보에 대한 정적 테스트
- 대표 메뉴 데이터가 이름, 가격, 설명, 이미지 대체 텍스트를 모두 포함하는지 확인

### 시각 검증

- 약 390px 모바일, 768px 태블릿, 1440px 데스크톱에서 전체 페이지 확인
- 긴 한글 문구, 메뉴 가격, CTA가 겹치거나 잘리지 않는지 확인
- 이미지의 주요 피사체가 `object-fit: cover` 상태에서도 보이는지 확인
- 모바일 고정 예약 바와 푸터가 겹치지 않는지 확인

### 배포 검증

- GitHub에 변경 내용을 반영한 뒤 Vercel 자동 배포 성공 확인
- 공개 URL에서 페이지 제목, 본문, 사진, 모든 예약·전화·길찾기 링크 확인
- 브라우저 콘솔 오류와 누락된 정적 파일 확인

## 12. 배포와 후속 작업

구현이 완료되면 현재 Vercel 프로젝트에 배포한다. 커스텀 도메인은 사이트 완성 및 실제 정보 검수 후 연결한다. 향후 필요할 경우 영문 페이지, 전체 메뉴 페이지, 지도 SDK, 관리자 화면, 예약 전환 분석을 별도 작업으로 추가한다.
