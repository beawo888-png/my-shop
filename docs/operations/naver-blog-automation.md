# 네이버 블로그 '메뉴추천' 매일 자동 발행

판교점·모란본점 네이버 블로그의 **메뉴추천** 카테고리에 매일 **오전 10시**에 메뉴 소개 글을 한 편씩 자동으로 올린다.

> Pencil(`초안`) 스케치 단계는 해당 없음: 사이트 화면을 바꾸지 않는 사장님 PC 자동화다.

| 지점 | 블로그 |
| --- | --- |
| 판교점 | `blog.naver.com/wangjing_lamb` |
| 모란본점 | `blog.naver.com/ruilian417` |

- 원고집: `content/blog/menu-posts.json` (메뉴 28개 × 글감 두 벌)
- 지점 안내(주소·지도·예약 링크): `lib/blog/branch-info.mjs` (홈페이지 `lib/site-content.ts`와 같은 내용)
- 사진: 홈페이지 메뉴 사진(`public/images/wangjing/menu/`)과 지점 외관 사진
- 실행: 사장님 PC의 **작업 스케줄러**가 10:00에 실행하고, 10:40에 한 번 더 실행해 놓친 지점을 올린다
- 기록: `.smartplace/blog-log.jsonl`, 화면 `.smartplace/screenshots/blog-*.png`, 실행 로그 `.smartplace/blog-task.log`

**네이버 비밀번호는 어디에도 저장하지 않는다.** 스마트플레이스 자동화와 같은 지점별 전용 브라우저 창에 한 번 로그인해 두고 그 로그인을 계속 쓴다.

## 글은 이렇게 만들어진다

1. 메뉴가 원고집 순서대로 하루에 하나씩 나간다. 2026-11-02에 판교점은 첫 메뉴(통양다리구이), 모란본점은 가운데 메뉴(가지튀김)부터 시작한다.
   그래서 같은 날 두 블로그에는 늘 다른 메뉴가 나가고, 한 블로그에서는 28일 동안 같은 메뉴가 다시 나오지 않는다.
2. 메뉴마다 제목·도입·맛 소개·곁들임 글이 두 벌(A·B)씩 있다. 같은 메뉴라도 두 블로그에는 다른 벌이 나가고, 28일마다 벌이 바뀐다.
   네이버가 두 블로그 글을 '유사 문서'로 보지 않게 하려는 것이다.
3. 글 순서: 인사 → 도입 → **메뉴 사진** → 이런 맛이에요 → 함께 드시면 좋아요 → 메뉴 정보(이름·추천 조합)
   → 지점 안내(상호·주소·오시는 길·주차·단체석·전화·**네이버 지도 링크**·**네이버 예약 링크**) → **지점 외관 사진** → 맺음말
4. 태그: 지점 태그(판교맛집 등) + 메뉴 태그 + 공통 태그, 30개 이하

메뉴를 고치거나 늘리려면 `content/blog/menu-posts.json`을 고치고 `npm run blog:check`로 확인한다. **가격은 넣지 않는다**(판교점과 모란본점 가격이 다르다). 원고에 가격이 들어가면 점검에서 걸린다.

## 매일 일어나는 일

10:00 작업(`npm run blog:post`, `scripts/blog/post-daily-menu.mjs`)은 지점마다 아래 순서로 처리한다.

1. 지점별 전용 브라우저 창을 열고 새 탭에서 `blog.naver.com/<블로그아이디>/postwrite`(글쓰기)를 연다.
   로그인이 풀려 있으면 알림 창을 띄우고, 사장님이 그 창에서 로그인할 때까지 20분 기다린다.
   스마트플레이스 작업이 크롬 창을 쓰고 있으면 2분마다 다시 시도한다(최대 60분).
2. '작성 중인 글이 있습니다' 창이 뜨면 이어 쓰지 않고 새로 쓴다.
3. 제목을 넣고, 본문을 붙여 넣고, 사진 자리에 사진을 올린다.
4. '발행'을 눌러 카테고리를 **메뉴추천**으로 고르고 태그를 넣은 뒤 최종 '발행'을 누른다.
5. 결과를 `.smartplace/blog-log.jsonl`에 남긴다. 그날 이미 발행한 지점은 다시 올리지 않는다(10:40 실행이 있어도 두 번 올라가지 않는다).

## 처음 한 번만 하는 설정 (사장님 PC)

프로젝트 폴더(`C:\vibecoding\my-shop`)에서 진행한다.

```powershell
git pull
npm install
```

### 1. 블로그마다 '메뉴추천' 카테고리 만들기

판교점·모란본점 블로그 각각에서:

> 내 블로그 → **관리** → **메뉴·글·동영상 관리** → **블로그** → **카테고리 추가** → 이름 `메뉴추천` → **확인**

이름이 정확히 `메뉴추천`이어야 한다(띄어쓰기 없음). 없으면 발행하지 않고 알림 창을 띄운다.

### 2. 지점별 로그인 확인

```powershell
npm run blog:setup
```

판교점 → 모란본점 순서로 브라우저 창이 뜬다. 스마트플레이스 자동화와 같은 지점별 창이다.

1. 그 지점 아이디로 로그인돼 있는지 본다. 아니면 로그인하고 **'로그인 상태 유지'를 체크**한다.
2. 블로그 글쓰기 화면이 뜨면 터미널에서 엔터. (글은 쓰지 않는다)

스마트플레이스에 쓰는 아이디와 블로그 아이디가 다르면 그 창의 로그인이 서로 바뀌어 버린다. 그럴 때는 알려 주면 블로그 전용 창을 따로 두도록 바꾼다.

### 3. 시험 실행 (최종 발행은 누르지 않음)

```powershell
npm run blog:test
```

판교점 창부터 제목·본문·사진·카테고리·태그가 채워지고 **최종 '발행' 직전에서 멈춘다**. 눈으로 확인하고 터미널에서 엔터를 누르면 모란본점으로 넘어간다.
쓰던 글은 발행되지 않고 네이버 임시저장에만 남는다(다음 실행 때 이어 쓰지 않고 새로 쓴다).

### 4. 매일 10시 예약 등록

```powershell
npm run blog:schedule
```

작업 스케줄러에 `WangjingNaverBlogMenu`가 등록된다(매일 10:00, 10:40). 지우려면 `npm run blog:unschedule`.

## 자주 쓰는 명령

| 명령 | 하는 일 |
| --- | --- |
| `npm run blog:preview` | 오늘 올라갈 두 글을 터미널에 보여 준다(브라우저 안 염) |
| `npm run blog:preview -- --date=2026-11-05` | 그날 글 미리 보기 |
| `npm run blog:check` | 원고집 점검 + 앞으로 2주 메뉴 일정 |
| `npm run blog:test` | 최종 발행 직전까지 채우기 |
| `npm run blog:post -- --branch=moran` | 모란본점만 지금 발행 |
| `npm run blog:post -- --force` | 오늘 이미 올렸어도 한 번 더 발행 |

## 화면이 바뀌었을 때

네이버가 글쓰기 화면을 바꾸면 멈추고 알림 창을 띄운다. 그때 화면은 `.smartplace/screenshots/blog-*.png`에 남는다.
버튼을 못 찾는 경우 `.smartplace/config.json`에 `"blogSelectors"`를 넣어 덮어쓸 수 있다. 기본값은 `lib/blog/editor.mjs`의 `DEFAULT_BLOG_SELECTORS`.

```json
{
  "blogSelectors": {
    "imageButton": "button[data-name='image']"
  }
}
```

블로그 아이디가 바뀌면 `config.json`의 `branches.<지점>.blogId`로 덮어쓴다(`npm run blog:setup`에서 입력해도 된다).

## 알고 쓸 것

- 블로그 글쓰기는 공식 API가 없어 브라우저를 대신 조작한다. 자동화 도구 사용은 네이버 이용약관에 걸릴 수 있고, 블로그 저품질 판정 위험이 있다.
- 10시에 PC가 켜져 있고 윈도우에 로그인돼 있어야 한다.
- 원고집이 28일마다 돌고 56일이면 같은 글이 다시 나온다. 새 사진·새 이야기를 원고집에 조금씩 더하면 좋다.
